# 201.81F — Palmistry Engine Expansion

## Status
Implemented. Full regression: **198/198 tests passing**.

## Scope
Palmistry is implemented as a structured evidence producer and stops at the explicit mapping boundary:

`IMAGE → QUALITY → HAND DETECTION / ORIENTATION → HAND STRUCTURE → THUMB → MOUNTS → MAJOR LINES → MINOR LINES → MARKINGS → OBSERVATION → USER CONFIRMATION → FEATURE CONFIDENCE → STRUCTURED SIGNAL CANDIDATE → EXPLICIT ONTOLOGY MAPPING`

## Implemented controls
- Left/right/both/unknown hand identity.
- Image quality assessment with blur, lighting, framing and obstruction inputs.
- Hand-detection and orientation confidence gates.
- Structured models for hand structure, thumb, mounts, major/minor lines and markings.
- Major-line taxonomy includes Life, Head, Heart, Fate, Sun/Apollo and Mercury/Health lines; additional traditional lines are represented without forcing interpretation.
- Candidate → confirmed/rejected workflow; CV output is never treated as user-confirmed evidence.
- Feature confidence propagates the strictest upstream uncertainty and optionally incorporates explicit user confirmation.
- Rejected/unconfirmed observations cannot generate signal candidates.
- Deterministic evidence-cluster identifiers prevent accidental double counting.
- Signal candidates preserve source variable, side, strength, confidence, relevance and methodology/calculation versions.
- Explicit `map_confirmed_signal()` boundary requires authoritative upstream mapping and confirmation.
- Medical, disease, exact lifespan, death-event and accident-event inference is explicitly prohibited.
- No exact lifespan or deterministic death/accident claims are generated by the engine.

## Architectural boundary
The Palmistry engine does **not** infer Theme, Sub-Theme, Axis or Pole semantics. Those must be supplied through the versioned Signal Mapping Registry and the common Evidence/Signal layer. Missing mappings remain missing evidence rather than negative evidence.

## Release note
This milestone expands the Palmistry evidence layer only. Computer-vision model selection, secure production image object storage, upload validation, and production identity/access controls remain deployment/release gates.
