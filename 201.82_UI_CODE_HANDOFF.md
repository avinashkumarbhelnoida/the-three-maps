# THE THREE MAPS — 201.82 UI CODE HANDOFF

## Purpose
This milestone replaces the old MVP frontend with a premium, editorial, intelligence-first interface suitable for handing to Claude for further implementation/refinement.

## Files
- `src/three_maps/frontend/index.html`
- `src/three_maps/frontend/styles.css`
- `src/three_maps/frontend/app.js`

## Design direction
- Dark obsidian foundation
- Restrained antique-gold accent
- Cinzel for brand/display labels
- EB Garamond for editorial/interpretive typography
- DM Sans for controls/data
- No zodiac clip-art, crystals, star-field clichés, or mystical visual noise
- Data visualization and geometry communicate the three-map concept
- Mobile responsive

## UX flow
LANDING → YOUR DATA → YOUR QUESTION → YOUR MAP → CONVERGENCE → THE INSIGHT → TRANSPARENCY

## Important architecture rule
The frontend remains presentation-only. It must not calculate Astrology, Numerology, Palmistry, convergence, contradiction, fusion, confidence, or timing. It consumes structured V1 API output only.

## API integration
The live path currently uses:
- `POST /v1/analyses`
- `GET /v1/analyses/{analysis_id}`
- `GET /v1/analyses/{analysis_id}/lineage`

The frontend also has a clearly bounded demo fallback when the API is unavailable. This fallback must never be presented as a real analysis in production; replace it with a proper authenticated loading/error state before deployment.

## Claude handoff instructions
1. Preserve the V1 engine and API ownership boundaries.
2. Do not move calculation/business logic into the browser.
3. Keep the visual language and information hierarchy unless there is a strong UX reason to change it.
