# 201.80H — SECURITY + PRIVACY REVIEW

## Status
Implemented baseline API hardening and security regression tests.

## Controls implemented
- Strict Pydantic request models with `extra="forbid"`.
- Latitude/longitude bounded to valid geographic ranges.
- Requested map allow-list: ASTROLOGY, NUMEROLOGY, PALMISTRY.
- Duplicate/unknown map requests rejected.
- Name length bounded to 200 characters.
- Analysis identifier format/length validation on retrieval routes.
- Request `Content-Length` limit of 1 MB.
- Security response headers: `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Cache-Control`.
- No secrets, tokens, or raw personal input are written by the API logging layer.
- Palm-image persistence is not implemented; therefore no image retention is introduced at this stage.

## Privacy principles
1. Collect only fields required for requested calculations.
2. Keep raw inputs separate from derived results.
3. Do not expose internal exception details as a default production contract.
4. Treat birth data, names, coordinates and palm images as sensitive user-provided data for product design purposes.
5. Persistence, authentication, authorization and retention policy must be established before production storage.

## Release blockers still open
- Authentication and per-user authorization are required before multi-user persistent deployment.
- Durable database access must enforce tenant/analysis ownership.
- Palm upload needs MIME/type, size, decompression-bomb and malware controls before activation.
- Production CORS policy must be explicit rather than permissive.
- TLS, secret management, rate limiting, structured security logging and backup/retention policy belong in deployment configuration.
- In-memory storage remains unsuitable for production.

## Test result
154 tests passed after adding five security regression tests.
