## Explicit release limitations / gates

### 🔴 Authoritative ontology gate

The canonical **20 Themes / 200 Sub-Themes** catalogue and authoritative mappings have not been invented or inferred. The architecture accepts them, but production semantic coverage requires the authoritative catalogue to be loaded and versioned.

### 🟡 Production infrastructure gate

Before real multi-user production deployment, configure:

- External identity provider
- TLS termination
- Production rate limiting
- Explicit production CORS allowlist
- Secret management
- PostgreSQL/Supabase or equivalent production database adapter
- Secure palm-image object storage and upload validation
- Backup and disaster-recovery controls
- Retention/deletion operations
- Production monitoring and alerting

### 🟡 Methodology expansion

The Astrology Yoga layer requires a versioned implementation covering formation, strength, context, and activation before yoga-derived signals are treated as production-authoritative.

Numerology Y-vowel handling must remain methodology/configuration controlled.

## Non-negotiable architecture rules

- Code implements methodology; code must not redefine methodology implicitly.
- AI/explanation cannot create upstream evidence.
- Aggregate polarity cannot be substituted for contradiction polarity.
- Dual-pole support does not imply contradiction.
- S6 and S7 are mutually exclusive.
- Same evidence cluster cannot automatically qualify as independent evidence.
- Unavailable evidence is not negative evidence.
- PARTIAL does not automatically weaken the System Score.
- Coverage and Data Confidence remain distinct from Fusion Strength.
- Published historical results are immutable and versioned.

## Release acceptance

The RC is acceptable for **controlled MVP evaluation / internal pilot use** subject to the limitations above.

It is **not yet a claim of production readiness for unrestricted public, multi-user deployment**.
